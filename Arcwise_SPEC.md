# Arcwise v0.1 — спецификация Android-прототипа

Цель — установить подписанный APK на Android до 20.11.2026 и опубликовать приложение в RuStore до 27.11.2026. Приоритет — быстрый выпуск и проверка интерфейса на одном рабочем сценарии.

## Пользовательский сценарий

1. На стартовом экране нажать «Войти в деморежим». Вход доступен сразу.
2. В портфеле открыть два локальных счёта. Можно начать с двух пустых счетов «Счёт 1» и «Счёт 2» и дать возможность изменить их названия.
3. Добавить покупки одной рублёвой акции на оба счёта. В форме выбрать счёт и тип операции, указать тикер, количество в штуках и цену сделки в рублях. Журнал хранит покупки и продажи.
4. На экране портфеля переключиться между «Все счета» и конкретным счётом. Общая сводка объединяет позиции по тикеру. Карточка показывает остаток и среднюю цену покупки.
5. Открыть ассистента, отправить сообщение и получить локальный ответ с подписью «Демо». Подойдёт шаблон, сообщающий число позиций, либо подсказка по добавлению сделки.
6. В профиле переключить светлую и тёмную темы. Выход возвращает на стартовый экран. При повторном входе сделки доступны.

## Экраны и данные

Использовать актуальные мобильные макеты Arcwise: `design/Светлая_тема_Arcwise.png` и `design/Тёмная_тема_Arcwise.png`. Указать Arcwise как отображаемое название Android-приложения и в карточке RuStore. Использовать фирменный знак с кольцом и искрой на стартовом экране, в обзоре и на экране ассистента. Если макет показывает функции за пределами v0.1, объём реализации определяет эта спецификация. Сохранить их градиенты, карточки и стиль нижней навигации. Реализовать вход, обзор, портфель, карточку позиции, операцию, ассистента и профиль с выбором темы. На обзоре показать количество счетов, количество открытых позиций и сумму затрат по открытым позициям. Рыночные цены, графики доходности, цели, тарифы и уведомления отложены. Подпись для суммы — «Затраты по открытым позициям».

Цена сделки вводится вручную. Количество — целое положительное число. Тикер сохраняется в верхнем регистре без пробелов по краям. При покупке средняя цена по счёту пересчитывается взвешенно, при продаже средняя цена остатка сохраняется. Общая средняя рассчитывается по остаткам на счетах. Продажа сверх остатка на выбранном счёте отклоняется. При нулевом остатке позиция пропадает из списка, сделки остаются в журнале. Комиссии и операции задним числом отложены. Для денежных расчётов использовать BigDecimal или целые копейки с точным промежуточным расчётом, округлять на выводе.

## Технический план

Один Android-модуль на Kotlin и Jetpack Compose. Room хранит счета и журнал операций, DataStore хранит тему и состояние демовхода. Сценарий работает офлайн. В v0.1 нет регистрации, API котировок, внешней модели, собственного сервера, аналитических SDK или обязательных сетевых разрешений.

Порядок для Codex на Windows 10:

1. Создать каркас и запустить debug-сборку на телефоне.
2. Реализовать журнал, расчёты и экран портфеля. Проверить покупки, продажи и сохранение.
3. Добавить демовход, оформление обеих тем, карточку позиции и локальный чат.
4. Собрать подписанный release APK, установить на телефон и пройти критерии приёмки.

## Критерии приёмки

- На чистой установке в авиарежиме демовход открывает приложение.
- Покупки 2 SBER по 1 000 ₽ и 3 SBER по 1 100 ₽ на разных счетах дают общую позицию 5 шт. со средней ценой 1 060 ₽. Фильтр по счетам показывает 2 и 3 шт.
- Продажа 3 шт. с первого счёта отклоняется. Продажа 1 шт. с него оставляет 4 шт. в сводке по средней цене 1 075 ₽.
- После перезапуска операции и выбранная тема сохранены. Оба режима оформления читаемы, все видимые кнопки основного сценария работают. Демочат возвращает локальный ответ.
- Скриншоты для карточки сделаны из проверенного APK. Описание для RuStore — локальный учёт сделок и сводка портфеля по нескольким счетам. Не заявлять котировки, полноценный ИИ и синхронизацию.
